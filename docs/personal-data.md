# Personal data and privacy

The public repository contains reusable educational material. `.personal/` contains data about a specific user and is Git-ignored except for its instructional README.

Personal data includes candidate responses, scores, session timestamps, progress, weak areas, goals, employers, recruiters, dates, feedback, reflections, private questions, and custom sets. It must not appear in questions, public interview definitions, examples, commit messages, or contribution drafts.

Git ignore reduces accidental commits; it is not encryption. Avoid secrets, use appropriate device security, and check staged changes before committing. A clone works without any personal workspace.

To derive public content from private notes, the user must explicitly request it. Remove identifying/confidential details, rewrite it as general reusable knowledge, verify facts independently, and do not copy a company's confidential interview prompt.

**Never move personal content into public content unless the user explicitly asks.**
